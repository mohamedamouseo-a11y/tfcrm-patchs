نفّذ فقط:
1) cd /tmp && rm -rf tfcrm-patchs && git clone --depth 1 https://github.com/mohamedamouseo-a11y/tfcrm-patchs.git
2) cd /tmp/tfcrm-patchs/TFCRM-Smart-Search-Phase2-Fuzzy-V1
3) python3 APPLY_PATCH.py /var/www/TFCRM
4) cd /var/www/TFCRM
5) npx vitest run server/utils/smartSearch.test.ts
6) npm run build
7) بعد نجاح الـBuild فقط: حدّد PM2 process/ processes التي pm_cwd الخاص بها يساوي /var/www/TFCRM بالضبط، واعمل Restart لها فقط.
8) تأكد أن TFCRM رجع online وHTTP 200.

المطلوب من Phase 2:
- Phase 1 exact/normalized/partial search يفضل الأولوية الأولى.
- Fuzzy لا يشتغل إلا لو Phase 1 رجع 0 نتائج.
- يدعم حرف ناقص / زائد / مختلف / تبديل حرفين متجاورين.
- عربي وإنجليزي بعد نفس normalization بتاع Phase 1.
- numeric-only search مثل أرقام الموبايل لا يستخدم fuzzy.
- multi-word query: كل token لازم يلاقي match.
- الحفاظ الكامل على Client Pool permissions/team/account-manager filters.
- fuzzy candidate set محدود بحد أقصى 1000 عميل بعد تطبيق الصلاحيات والفلاتر.
- list وstats يفضلوا متسقين.

اختبارات عملية مقترحة بعد النشر:
- ابحث باسم/شركة موجودة كتابة صحيحة وتأكد أن النتيجة الطبيعية لم تتغير.
- لو عندك عميل اسمه/شركته Furniture، جرب typo قريب مثل Furntiure أو Furnture.
- جرب typo عربي بسيط في اسم عميل موجود.
- جرب رقم هاتف صحيح ثم رقم هاتف به رقم خاطئ: يجب ألا يعمل fuzzy على الرقم الخاطئ.
- جرب نفس typo تحت Account Manager محدود الصلاحيات وتأكد أنه لا يرى أي عميل خارج scope.
