المطلوب من الباتش:
A) Global Search:
- P1 Arabic/English normalization على Server.
- P2 fuzzy fallback فقط لو exact/normalized result لنوع النتيجة = 0.
- أقصى fuzzy candidates = 500 لكل نوع.
- نفس النتائج المجمعة Deals / Companies / Contacts تظل هي Suggestions الحالية.
- إضافة Mic بنفس Browser SpeechRecognition المستخدم سابقًا؛ transcript يدخل نفس q state.
- الحفاظ على owner scope الحالي للـbd_rep وbd_viewer في Deals.

B) Companies:
- P1 normalized server search على name/domain.
- P2 fuzzy fallback بحد أقصى 1000 candidate.
- الحفاظ على country filter + limit + offset + total.
- P3 suggestions بحد أقصى 6 من نفس server results، بدون API إضافي.
- P4 mic -> نفس search state.

C) Contacts:
- P1 normalized server search على fullName/email/phone.
- P2 fuzzy fallback بحد أقصى 1000 candidate.
- numeric-only typo مثل رقم هاتف خاطئ لا يعمل له fuzzy.
- الحفاظ على companyId filter + limit + offset + total.
- P3 max 6 suggestions من نفس results.
- P4 mic -> نفس search state.

D) Deals:
- Server list endpoint: normalized/fuzzy title search مع الحفاظ على pipelineId/stageId/ownerId/limit/offset.
- Kanban search: P1/P2 local على title + companyName من البيانات المحملة.
- P3 max 6 suggestions من loaded deals.
- P4 mic -> نفس search state.

اختبار Live بعد النشر:
1) Global Search (Ctrl/Cmd + K):
   - عربي: جرّب اختلافات الألف/التشكيل لاسم موجود.
   - English: case-insensitive.
   - typo بسيط لصفقة/شركة/Contact موجود.
   - جرّب Mic بالعربي والإنجليزي.
2) Companies:
   - exact ثم typo بسيط.
   - تأكد Suggestions بعد حرفين وبحد أقصى 6.
   - جرّب Mic.
   - غيّر country filter وتأكد أنه ما زال محترمًا.
3) Contacts:
   - exact ثم typo في الاسم.
   - جرّب رقم هاتف صحيح.
   - جرّب رقم هاتف به رقم خاطئ وتأكد أنه لا fuzzy-match.
   - Suggestions + Mic.
4) Deals Kanban:
   - exact وtypo في title أو companyName.
   - Suggestions + Mic.
   - تأكد pipeline/stage/drag-drop لم تتأثر.
5) Permission scope:
   - بحساب bd_rep أو bd_viewer: Global Search Deals لا تعرض صفقات خارج owner scope الحالي.
